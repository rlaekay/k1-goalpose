
### §8-72 부기 4 — `NE`↔`NZ` 는 **✅ 로 복귀한다.** `2076c49` 가 no-op 임을 코드로 확인 (2026-08-09 23:3x)

분석 세션이 *"계보 B 표는 21:00 런을 썼고 그건 `NZ` 와 `2076c49` 하나가 갈린다"* 를 찾았고,
두 갈래를 줬다: ① `2076c49` 가 no-op 임을 확인 ② 19:10 런으로 재채점(sha 가 `NZ` 와 동일).

⛔ **② 는 불가능하다** — `2026-08-07-19-10-29_NE_ctrl100` 의 `nn/` 에 **체크포인트가 0개**다.
그 런은 아무것도 안 남겼고, **그래서 표가 21:00 런을 쓴 것**이다. 선택 규칙의 문제가 아니라
**선택지가 하나뿐이었다.**(분석 세션이 "왜 더 나쁜 쪽이 뽑혔나" 를 물었는데 답은 이것이다.)

⇒ **① 을 코드로 했다.** `NE`(21:00)·`NZ` 학습 config 는 둘 다
`history_steps 1` · `extra_dof_tau/extra_foot_offset False` · `obs_delay_steps [0,0]` · `num_obs 54` 다.

**`goal_pose_v3.py`(미러 맵)** — 새 코드가 `frame_w = 54`, `hist_k = 1` 을 만들고
`perm = list(range(54))` · `sign = [1.0]*54` 로 시작한다. 옛 코드는
`perm = list(range(self.num_obs))` = `list(range(54))` 였다 ⇒ **동일.**
확장 채널 블록은 `foot_at`/`tau_at` 이 `None` 이라 건너뛰고, 타일링은 `hist_k > 1` 가드 안이다.
⇒ **바이트 수준으로 같은 동작.**

**`goal_pose.py`(이력·지연 버퍼 prime 제거)** — 제거된 두 줄이 건드리던 버퍼가
**이 config 에서는 생성되지 않는다**:
* `_obs_stack` : `if k <= 1: return` 로 조기 반환(`history_steps = 1`) ⇒ **존재하지 않음.**
  제거된 코드는 `hasattr(self, "_obs_stack")` 가드 안이었으므로 **이미 no-op 이었다.**
* `_obs_hist` : `if not cfg or int(cfg[1]) <= 0: return`(`obs_delay_steps [0,0]` ⇒ `cfg[1]=0`)
  ⇒ **존재하지 않음.**

⇒ **`2076c49` 는 `NE`/`NZ` 두 config 에서 검증된 no-op 이다. `NE`↔`NZ` 는 ✅ 로 복귀한다.**
`CLAUDE.md` 의 *"깨끗한 한 레버 비교는 `NE` 대 `NZ` 하나뿐"* 이 **코드 축에서도 성립한다.**

⭐ 이것이 `claim_check` 의 ⛔ 를 빠져나가는 **정당한 경로의 첫 사례**다 — 도구가 요구하는
*"그 커밋들이 이 config 에서 no-op 임을 사람이 확인해서 적는다"* 를 **가드 조건까지 읽어서**
했다. 값이 같다가 아니라 **코드 경로가 안 돈다**는 확인이라는 점이 중요하다.
